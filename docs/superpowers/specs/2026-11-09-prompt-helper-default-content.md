# 프롬프트 헬퍼 기본 콘텐츠 (첫 버전)

앱에 기본으로 들어가는 템플릿, 문구 모음, 가이드 항목이다. 설계 문서([2026-11-09-prompt-helper-design.md](2026-11-09-prompt-helper-design.md))와 함께 읽는다. 근거는 [조사 문서](../../research/2026-11-09-ai-prompting-research.md)에 있다.

## 0. 표기 규칙

- 섹션 제목은 `## 제목`으로 통일한다. 세 AI 모두에서 문제없이 쓰이고, 가이드 패널이 제목으로 섹션을 알아본다.
- `{힌트}`: 사용자가 채울 빈칸이다. 중괄호 안에는 짧은 힌트만 넣는다. 예시 문장은 넣지 않는다(가이드 방식 C).
- `{{today}}`: 붙여넣을 때 앱이 오늘 날짜(YYYY-MM-DD)로 바꿔 넣는 자동 변수다.
- 템플릿 끝의 마지막 문장은 **추천 끝맺음**이다. 미리 채워진 채로 들어간다. 사용자는 필요 없으면 지우면 된다.
- AI별 버전의 차이는 이렇다.
  - Claude Code: 붙여넣는 자료를 XML 태그로 감싼다. 범위를 분명히 한다. 진행 방식은 "계획 먼저"를 기본으로 둔다.
  - Codex: 가장 짧게 쓴다. 단계 목록은 쓰지 않고, 결과와 완료 조건만 쓴다.
  - Gemini: 자료를 먼저 두고 "위 자료를 바탕으로"로 잇는다. 원하는 상세도를 명시한다. 핵심 제약은 끝에 한 번 더 쓴다. 단계는 한 번에 하나씩만 요청한다.

## 1. 기본 템플릿 (5종 × 3모드)

### 1.1 기획 문서 (기본 단축키 ⌃⌥1)

**Claude Code**
```
## 목적과 독자
{어떤 문서} — 독자: {누가} / 이 문서로 정할 것: {결정}

## 확정된 것
{장르·플랫폼·핵심 규칙 등}

## 아직 정하지 않은 것
{미정 항목}

## 참고
@{기존 문서}

## 결과물
파일: {docs/경로.md} / 분량: {약 N쪽}
문단 위주로 쓰고, 표는 비교할 때만 써줘. 근거 없는 수치는 [미정]으로 표시해줘.

바로 쓰지 말고 먼저 나를 인터뷰해서 빈칸을 채운 뒤 작성해줘
```

**Codex**
```
## 목표
{어떤 문서를, 누가 읽고, 무엇을 정하려는지}

## 맥락
@{기존 노트} / {핵심 콘셉트·타깃·플랫폼}

## 출력
{docs/경로.md}, 목차: {섹션 목록}, 분량: {대략}, 문단 위주(표는 비교할 때만)

## 완료 조건
각 항목에 목적·규칙·예외·미해결 질문이 있고, 끝에 [미정] 목록이 있음

먼저 나를 인터뷰해서 빈칸을 채운 뒤 작성해줘
```

**Gemini**
```
## 자료
{기존 메모·레퍼런스 붙여넣기}

## 목표
위 자료를 바탕으로 {어떤 문서}를 쓰려고 해. 독자: {누가} / 이 문서로 정할 것: {결정}

## 출력 형식
{섹션 목록}, 총 {분량}, 한국어로 자세하게

## 제약
자료에 근거한 내용만 사실처럼 쓰고, 나머지는 '가정'으로 표시해줘

이번 답변에서는 목차만 제안해줘. 본문은 목차를 확인한 뒤 따로 요청할게
```

## 2. 기본 문구 모음

검색 팝업과 메뉴바에서 고르면 커서 위치에 들어가는 문장들이다. 문구마다 분류가 있다. `추천 모드`가 있는 문구는 그 모드일 때 목록 위쪽에 보이고 "추천" 표시가 붙는다. 다른 모드에서도 고를 수는 있다.

| 분류 | 문구 | 추천 모드 |
|---|---|---|
| 진행 방식 | 코드 전에 계획을 먼저 보여줘 | 전체 |
| 진행 방식 | 계획만 세우고 멈춰줘 | 전체 |
| 진행 방식 | 바로 쓰지 말고 먼저 나를 인터뷰해서 빈칸을 채워줘 | 전체 |
| 진행 방식 | 확인 질문 없이 맥락에서 판단해서 끝까지 진행해줘 | Codex |
| 진행 방식 | 이번 답변에서는 {첫 단계}까지만 해줘 | Gemini |
| 범위 | 요청 범위 밖의 수정은 하지 말고 끝에 제안만 해줘 | Claude Code |
| 범위 | 지금 있는 라이브러리만 써줘 | 전체 |
| 범위 | 테스트는 바뀐 부분과 관련된 것만 돌려줘 | Codex |
| 보고·검증 | {테스트 명령} 실행 후 명령과 결과를 보고해줘 | 전체 |
| 보고·검증 | 끝나면 바뀐 파일, 검증 결과, 남은 이슈를 정리해줘 | 전체 |
| 보고·검증 | 확인하지 못한 부분은 [미확인]으로 표시해줘 | 전체 |
| 자료·맥락 | 위 자료를 바탕으로 | Gemini |
| 자료·맥락 | 위 자료만 근거로 답해줘 | Gemini |
| 자료·맥락 | 작업 전에 {규칙 파일}을 먼저 읽어줘 | 전체 (모드에 따라 CLAUDE.md / AGENTS.md / GEMINI.md로 자동 치환) |
| 출력 | 결론부터 말해줘 | 전체 |
| 출력 | 자세하게 설명해줘 | Gemini |
| 출력 | 문단 위주로 쓰고, 표는 비교할 때만 써줘 | 전체 |

`{규칙 파일}`은 붙여넣을 때 현재 모드에 맞게 바뀌는 자동 변수다. `{{today}}`처럼 앱이 채운다. 구현에서는 `{{rulesFile}}`로 표기한다.

## 3. 가이드 항목

편집 화면 오른쪽 패널에 보이는 내용이다. 커서가 있는 섹션의 **제목 텍스트**로 항목을 찾는다. 예를 들어 "## 완료 조건" 아래에 커서가 있으면 `완료 조건` 항목이 보인다. 한 항목에는 여러 제목이 연결될 수 있다. 예를 들어 `참고`, `맥락`, `관련 파일`은 하나의 항목을 공유한다. 사용자가 만든 섹션처럼 연결된 항목이 없으면 일반 팁을 보여준다.

항목마다 들어가는 내용은 네 가지다.
- 왜 필요한지 (1~2문장)
- 좋은 예와 나쁜 예 (각 1개)
- 이 모드에서만 해당하는 팁 (선택)
- 출처

| 항목 (연결 제목) | 왜 필요해요 | 좋은 예 ✓ / 나쁜 예 ✗ | 모드별 팁 |
|---|---|---|---|
| 목표 (목표, 목적과 독자, 질문) | 무엇을 왜 하는지 알면 AI가 애매한 지점에서 맞는 쪽으로 판단해요 | ✓ "로그인에 Google 로그인 추가 — 이유: 가입 중 이탈 줄이기" / ✗ "로그인 개선해줘" | Codex: 결과만 쓰고 방법은 맡겨요 |
| 맥락 (참고, 맥락, 관련 파일, 대상, 단서, 의심 위치) | 파일을 말로 설명하는 것보다 직접 첨부하는 게 정확해요 | ✓ "@src/auth/kakao.ts 처럼 만들어줘" / ✗ "카카오 로그인 코드 있잖아, 그거처럼" | 기술 스택·폴더 구조는 AI가 직접 읽으니 쓰지 않아도 돼요 |
| 자료 (자료, 에러·로그) | 긴 자료는 맨 앞에 두고 지시는 뒤에 두면 답이 좋아져요 | ✓ 로그를 맨 위에 붙이고 질문은 아래에 / ✗ 질문 중간에 로그를 끼워 넣기 | Claude: `<error_log>` 같은 태그로 감싸요. Gemini: 뒤에서 "위 자료를 바탕으로"로 이어요 |
| 범위 (범위와 제약, 범위, 제약) | 어디까지 손댈지 정하지 않으면 AI가 범위를 넓히거나 엉뚱한 곳을 고쳐요 | ✓ "제외: 결제 모듈은 그대로" / ✗ 범위 없이 "알아서 잘" | Claude: 범위를 넓히는 경향이 있어 특히 중요해요. Gemini: 핵심 제약은 끝에 한 번 더 써요 |

| 증상 (증상, 재현) | 재현 절차가 증상 설명보다 원인을 찾는 데 더 중요해요 | ✓ "1. 로그인 2. 새로고침 → 401" / ✗ "가끔 로그인이 풀려요" | 실패 테스트로 재현부터 시키면 수정 확인이 쉬워요 |
