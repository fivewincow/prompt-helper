## 1. 무엇을, 왜

AI 코딩 에이전트에게 일을 시킬 때 **잘 구조화된 프롬프트를 단축키 한 번으로 붙여넣게 해 주는** 데스크톱 상주 앱이다.

**만드는 이유.** 사용자는 Claude Code로 게임 기획서를 쓰게 했을 때 짧은 대화체로 요청했고, 맥락이 빠져서 결과가 아쉬웠다. 회사 사수에게서 `[목표] / [환경] / [지시사항]`처럼 섹션을 나눠 쓰면 잘 된다는 말을 들었다. 하지만 매번 이 구조를 손으로 쓰기는 번거롭다.

**앱이 하는 일.** AI별 공식 문서와 커뮤니티 자료로 검증한 템플릿을 단축키로 바로 꺼내 쓰게 한다. 앱은 AI를 대신 쓰지 않는다. **AI를 더 잘 쓰게 돕는 보조 도구**다 **(결정)**.

**사용자.** 처음에는 사용자 본인이 쓴다. 나중에 배포할 생각이 있다 **(결정)**. 사용자는 TS, React, Next, Spring을 다뤄 봤다.

**대상 AI.** Claude Code가 중심이다. Codex는 앞으로 쓸 예정이고, Gemini는 현재 쓰고 있다 **(결정)**.

**성공 기준.** 첫 버전이 성공했다고 볼 조건은 세 가지다.
- 사용자가 Claude Code로 개발할 때 매일 이 앱으로 프롬프트를 시작한다.
- "직관적으로 동작한다": 템플릿이 있고, 단축키를 누르면 빈칸을 채워 바로 붙여넣을 수 있다 **(결정)**.
- 쓰면서 템플릿과 문구를 조금씩 고치고 늘려 간다 **(결정)**.

## 2. 목표, 비목표, 반목표

### 첫 버전 목표
1. 기본 템플릿 5종: 기획 문서, 기능 개발, 테스트, 버그 수정, 긴 작업·자료 조사. 각각 AI 모드 3개(Claude Code / Codex / Gemini)별 버전이 있다 **(결정)**.
2. **AI 모드.** 현재 모드를 골라 두면 같은 단축키가 그 모드의 버전을 붙여넣는다 **(결정)**.
3. **템플릿 단축키와 채우기 창.** 단축키를 누르면 작은 채우기 창에 템플릿이 뜬다. 빈칸을 채운 뒤 붙여넣으면 원래 커서 위치에 들어간다. 설정에서 "바로 붙여넣기"로 바꿀 수 있다 **(결정)**.
4. **검색 팝업.** 단축키 하나로 작은 검색창을 열고, 템플릿과 문구를 검색해서 Enter로 넣는다 **(결정)**.
5. **메뉴바(맥) / 트레이(윈도우) 메뉴.** 여기서 모드 전환, 템플릿 넣기, 문구 넣기, 편집 창 열기, 설정을 한다 **(결정)**.
6. **편집 창.**
   - 템플릿과 문구를 직접 고치거나 추가하고, 기본 템플릿을 복제할 수 있다.
   - 모든 단축키를 원하는 키로 바꿀 수 있다.
   - 커서가 있는 섹션의 가이드(왜 필요한지, 좋은 예와 나쁜 예, 출처)를 보여준다 **(결정, 시안 확정)**.
7. 맥과 윈도우를 지원한다 **(결정)**.

### 비목표 (첫 버전에서는 하지 않음)
- **모바일.** 안드로이드와 iOS 커스텀 키보드는 나중에 한다 **(결정)**.
- **AI로 문장 다듬기.** API를 호출해 다듬는 기능은 넣지 않는다. 가이드는 안내 문구와 문구 모음으로만 제공한다 **(결정)**.
- **문구마다 단축키 지정.** 시안 C안을 고르지 않았다 **(결정)**.
- 기기 간 동기화, 자동 업데이트, 코드 서명과 배포 패키징, 템플릿 공유와 가져오기·내보내기 **(제안: 배포 단계에서 다룸)**
- 활성 앱을 보고 모드를 자동으로 바꾸는 기능 **(제안)**
- 템플릿을 Claude Code skill이나 Gemini 커맨드로 내보내기 **(제안: 나중에)**
- 리팩터링, 코드 리뷰 템플릿. 조사 결과는 있으니 나중에 추가한다 **(제안)**
- 리눅스

### 반목표 (기능은 돌아가도 이렇게 되면 실패)
- **무거운 상주 앱.** 하루 종일 떠 있는 도구라서 메모리와 시작 속도가 중요하다. 이 때문에 Electron을 쓰지 않는다 **(결정)**.
- **사용자의 클립보드를 망가뜨리는 것.** 붙여넣은 뒤 원래 클립보드 내용이 사라지면 안 된다 **(제안)**.
- **흔한 단축키를 말없이 가로채는 것** **(제안)**
- **예전 요령이 들어간 템플릿.** "step by step", "IMPORTANT" 강조, "꼼꼼히 확인해" 같은 것이다. 이 앱의 존재 이유는 조사로 검증된 작성법이다 **(제안)**.
- **서류 작성처럼 느껴질 만큼 긴 템플릿.** 빈칸은 짧은 힌트만 둔다(가이드 방식 C) **(결정)**.

## 3. 기술 스택 **(결정)**

- **Tauri 2 + React + TypeScript.** 화면, 편집, 설정, 검색 팝업은 모두 React + TS로 만든다.
- **Rust는 꼭 필요한 부분에만 쓴다.** 붙여넣기 키 입력 흉내, 이전 앱으로 포커스 되돌리기, 맥 손쉬운 사용 권한 확인 같은 OS 기능이다. 사용자는 Rust 경험이 없으니, Rust 코드에는 무엇을 왜 하는지 주석을 단다 **(제안)**.
- **Tauri 공식 플러그인을 우선 쓴다:** global-shortcut, clipboard-manager, tray, autostart, store 또는 fs. 키 입력 흉내용 크레이트(예: enigo)나 직접 구현 여부는 **(빌더 판단)**이다.
- 새 패키지를 설치하기 전에 사용자에게 묻는다. 사용자 전역 규칙이다.

## 4. 동작

### 4.1 AI 모드
- 모드는 Claude Code / Codex / Gemini 세 가지다. 현재 모드는 하나이고, 앱을 다시 켜도 유지된다.
- 메뉴바 아이콘 옆에 현재 모드를 짧게 표시한다(CC / CX / GM) **(제안)**. 트레이에서는 툴팁과 메뉴에 표시한다.
- 모드 전환 방법은 두 가지다.
  - 메뉴에서 선택한다.
  - 모드 전환 단축키(기본 ⌃⌥M)를 누르면 순환한다. 전환할 때 짧은 알림(토스트)으로 새 모드를 보여준다 **(제안)**.

### 4.2 템플릿 넣기: 채우기 창 → 붙여넣기 **(결정)**

**왜 채우기 창이 있나.**
- Claude Code CLI는 800자나 3줄을 넘는 붙여넣기를 `[Pasted text #1 +N lines]`로 접어서 보여준다(2026-11-09, v2.1.318에서 확인). 기본 템플릿은 모두 이보다 길다.
- 그래서 붙여넣은 뒤에는 CLI 입력창에서 `{빈칸}`을 고칠 수 없다.
- 해결 방법: 빈칸을 앱 안에서 먼저 채우고, 완성된 글을 붙여넣는다.

**흐름**
1. 사용자가 어떤 앱에서든 템플릿 단축키(기본 ⌃⌥1~5)를 누른다. 앱은 이때 앞에 있던 앱, 즉 붙여넣을 곳을 기억한다.
2. 화면 가운데 위쪽에 **채우기 창**이 뜬다.
   - 현재 모드의 템플릿이 들어 있다.
   - 자동 변수(`{{today}}`, `{{rulesFile}}`)는 이미 채워져 있다.
   - `{힌트}` 빈칸은 색으로 강조된다.
3. 첫 빈칸이 선택된 상태로 열린다. 사용자가 입력하면 빈칸이 그 내용으로 바뀐다.
4. 붙여넣기 키(⌘Enter / Ctrl+Enter)를 누르면 창이 닫힌다. 1에서 기억한 앱으로 포커스를 돌린 뒤 아래 "붙여넣기 처리"를 한다.

**채우기 창 조작**

| 키 | 동작 |
|---|---|
| Tab / Shift+Tab | 다음 / 이전 빈칸 선택 |
| Enter | 줄바꿈. 로그처럼 여러 줄인 내용을 넣을 수 있다 |
| ⌘Enter / Ctrl+Enter | 붙여넣기 |
| ⌘K / Ctrl+K | 문구 검색. 검색 팝업과 같은 목록이다. 고른 문구는 채우기 창의 커서 위치에 들어간다 **(제안)** |
| Esc | 취소. 아무것도 붙여넣지 않는다 |

- **빈칸 밖의 글도 자유롭게 고칠 수 있다.** 여기서 고친 내용은 이번 한 번만 쓰이고, 저장된 템플릿은 바뀌지 않는다.
- **빈칸이 남았을 때.** 채우지 않은 빈칸이 남은 채 붙여넣기를 누르면 "빈칸 N개가 남았어요"라고 알린다. 한 번 더 누르면 그대로 붙여넣는다 **(제안)**.
- **화면 구성.** 창 아래쪽에 조작 안내를 한 줄로 보여준다. 가이드 팁은 채우기 창에 넣지 않는다(가이드 방식 C) **(제안)**.
- **붙여넣기 키를 Enter에서 ⌘Enter로 바꾼 이유.** 사용자가 고른 미리보기에는 "Enter 붙여넣기"라고 적혀 있었다. 하지만 로그처럼 여러 줄을 넣어야 하는 경우가 있어서, Enter는 줄바꿈으로 두고 붙여넣기는 ⌘Enter로 했다 **(제안)**.

**바로 붙여넣기 설정.**
- 설정에서 템플릿 넣는 방식을 "채우기 창(기본)"과 "바로 붙여넣기" 중에서 고른다.
- 바로 붙여넣기를 고르면 채우기 창 없이 템플릿을 그대로 붙여넣는다.
- 이 설정은 모드와 상관없이 하나다 **(제안)**.

**붙여넣기 처리.** 채우기 창, 바로 붙여넣기, 검색 팝업, 메뉴가 모두 같은 방식을 쓴다.
1. 현재 클립보드 내용을 백업한다.
2. 넣을 텍스트를 클립보드에 넣는다.
3. 붙여넣기 키(⌘V / Ctrl+V)를 흉내 낸다.
4. 잠시 기다린 뒤 원래 클립보드를 복원한다.

**구현 시 주의할 점 (빌더용)**
- **수정키가 눌린 채로 붙여넣기가 나가면 안 된다.** 사용자가 아직 ⌃⌥를 누르고 있으면 ⌘V가 ⌃⌥⌘V로 나간다. 수정키가 떼어진 뒤에 보내거나, 그 상태를 처리해야 한다.
- **복원 대기 시간이 너무 짧으면** 대상 앱이 복원된 옛 내용을 붙여넣는다. 실제 앱들(아래 9절 목록)로 시간을 맞춘다.
- **클립보드 복원 범위.** 최소한 텍스트는 복원한다. 이미지나 서식 있는 내용까지 복원할지는 **(빌더 판단)**이다. 복원하지 못하는 형식이 있으면 문서에 남긴다.
- **터미널 CLI.** Claude Code CLI가 붙여넣은 글을 접어서 보여주는 것은 정상이다. 다음 두 가지를 확인한다.
  - 접힌 채로 제출해도 전체 내용이 AI에게 전달되는지
  - 여러 줄이 바로 제출되지 않고 입력창에 들어가는지

  Codex CLI와 agy는 이 맥에 설치돼 있지 않아서 확인하지 못했다.

### 4.3 검색 팝업
- 기본 단축키는 맥 ⌃⌥P, 윈도우 Ctrl+Alt+P다 **(제안)**.
  - 시안의 ⌥Space에서 바꿨다. 이유는 세 가지다.
    - 맥에서 ⌥Space는 ChatGPT 앱과 Raycast의 기본 키와 겹친다.
    - 윈도우에서 Alt+Space는 창 시스템 메뉴다.
    - ⌃⌥Space는 사용자 맥에서 "입력 메뉴에서 다음 소스 선택"(한/영 전환)으로 켜져 있다. 2026-11-09에 직접 확인했다.
  - 모든 기본 키를 ⌃⌥(Ctrl+Alt) 조합으로 통일했다. P는 Prompt/Palette에서 따왔다.
- 화면 가운데 위쪽에 작은 창이 뜬다. 검색어를 치면 템플릿과 문구를 함께 거른다.
  - 결과는 "템플릿", "문구 · 분류명" 그룹으로 묶는다.
  - 현재 모드의 추천 문구는 위쪽에 "추천" 표시와 함께 보인다.
- 조작: ↑↓로 이동, Enter로 넣기, Esc로 닫기. 검색어가 비어 있으면 최근 사용 항목을 먼저 보여준다 **(제안)**.
- **문구를 고르고 Enter를 누르면** 팝업을 닫는다. 그리고 **포커스를 팝업을 열기 전의 앱으로 되돌린 뒤** 4.2의 "붙여넣기 처리"로 넣는다. 포커스를 되돌리지 않으면 엉뚱한 곳에 붙는다. 이 부분이 가장 까다롭다.
- **템플릿을 고르면** 채우기 창이 열린다. 설정이 "바로 붙여넣기"면 문구처럼 바로 넣는다.

### 4.4 메뉴바·트레이 메뉴
시안 B를 따른다.
- 모드 (체크 표시)
- 템플릿 ▸ (템플릿 목록과 단축키 표시)
- 문구 ▸ (분류별로 묶인 목록)
- 템플릿 편집…
- 설정…
- 종료

메뉴에서 문구를 고르면 메뉴가 닫히고 직전 앱에 붙여넣는다. 템플릿을 고르면 채우기 창이 열린다(4.2).

맥에서는 Dock 아이콘 없이 메뉴바 앱으로 동작한다. 편집 창이 열려 있을 때만 창이 보인다 **(제안)**.

### 4.5 편집 창 (시안 확정)

**시안 파일**은 [mockups/](mockups/)에 있다.
- `editor.html`: 편집 창
- `phrase-picker.html`: 검색 팝업(A), 메뉴바(B)
- `guide-display.html`: 가이드 방식. C가 확정안이다.

이 파일들은 브레인스토밍용 조각 HTML이라서 브라우저로 바로 열면 기본 스타일이 빠진다. 레이아웃과 구성만 참고하고, 색과 세부 디자인은 빌더가 정한다.

위쪽에 탭이 세 개 있다: **템플릿 / 문구 / 단축키·설정**.

**템플릿 탭**
- **왼쪽**: 템플릿 목록과 각 단축키. "기본 템플릿"과 "내 템플릿"으로 나눈다. 새 템플릿을 만들거나 기본 템플릿을 복제할 수 있다.
- **가운데**
  - 위쪽에 모드 선택 버튼(Claude Code / Codex / Gemini)이 있다. 선택한 모드의 버전을 텍스트로 편집한다. 제목, 빈칸, 추천 끝맺음을 색으로 구분한다.
  - 아래쪽에서 단축키를 변경하거나 기본값으로 되돌린다. "다른 모드에 복사" 기능도 여기 있다.
- **오른쪽**: 가이드 패널. 커서가 있는 섹션의 제목으로 가이드 항목을 찾아 보여준다. 연결 규칙과 내용은 기본 콘텐츠 문서 3절에 있다.
  - **출처**는 공식 문서의 제목과 URL로 표시한다. 누르면 기본 브라우저로 연다. 조사 문서는 앱에 넣지 않는다 **(제안)**. 항목별·모드별 URL은 기본 콘텐츠 문서 3.1절에 있다.
- **템플릿 이름과 순서**를 바꿀 수 있다. 내 템플릿은 삭제할 수 있다. 기본 템플릿은 숨기거나 "기본값으로 되돌리기"만 할 수 있다 **(제안)**.
- **빈 버전 처리.** 한 템플릿의 일부 모드 버전이 비어 있으면, 그 모드에서 단축키를 눌렀을 때 Claude Code 버전을 대신 쓰고 토스트로 알린다 **(제안)**.

**문구 탭**
- 분류별 목록이다. 문구를 추가, 수정, 삭제할 수 있고 분류와 추천 모드를 지정한다.

**단축키·설정 탭**
- 검색 팝업 키, 모드 전환 키, 템플릿 단축키를 한곳에서 본다.
- 템플릿 넣는 방식: 채우기 창(기본) / 바로 붙여넣기 **(결정)**.
- 로그인 시 자동 실행을 켜고 끈다. 기본값은 켜짐이다 **(제안)**.
- 맥이면 손쉬운 사용 권한 상태를 보여준다.

### 4.6 단축키 변경과 충돌 경고
- 키 입력 칸을 누르고 원하는 조합을 누르면 녹화된다.
- **경고를 띄우는 경우**
  - 앱 안에서 이미 쓰는 키와 겹칠 때. 저장하지 못하게 막는다.
  - OS 등록에 실패했을 때. 다른 앱이 이미 차지한 경우다.
  - **맥 시스템 단축키 설정에서 켜져 있는 키와 겹칠 때.** 예: 입력 소스 전환 ⌃Space / ⌃⌥Space, Spotlight ⌘Space. 이런 키는 OS가 등록 실패를 알려주지 않을 수 있다. 그래서 시스템 단축키 설정(`com.apple.symbolichotkeys`)을 읽어서 확인한다 **(제안, 읽는 방법은 빌더 판단)**.
  - 흔히 쓰는 키 목록과 겹칠 때. 예: ⌘C, ⌘V, ⌘⌥1~3(문서 앱의 제목 단축키) **(빌더 판단: 목록 범위)**
- 다른 앱 안에서만 쓰는 단축키(예: Slack 내부 단축키)는 OS가 알려주지 않아서 감지할 수 없다. 시안의 "Slack과 겹쳐요"는 예시일 뿐이고, 실제 경고는 위 세 경우로 한정한다.
- 수정키 없는 단일 키(예: `A`)는 등록하지 못하게 한다 **(제안)**.

### 4.7 처음 실행 (맥)
- 붙여넣기 흉내에는 **손쉬운 사용 권한**이 필요하다. 처음 실행하면 이유를 짧게 설명하고, 시스템 설정의 해당 화면을 여는 버튼을 보여준다.
- **권한이 없을 때의 대체 동작 (제안)**
  - 붙여넣기 처리 대신, 완성된 텍스트를 클립보드에만 넣는다. 이 경우 원래 클립보드는 복원하지 않는다.
  - "⌘V로 붙여넣으세요 · 권한을 켜면 자동으로 붙여넣어요" 알림을 띄운다.

## 5. 템플릿 형식 **(결정: 가이드 방식 C)**
- 섹션 제목은 `## 제목`이다.
- 빈칸은 `{짧은 힌트}`로 쓴다. 예시 문장은 넣지 않는다.
- 추천 끝맺음 문장은 미리 채워 둔다.
- 자동 변수는 `{{이름}}` 형식이다. 첫 버전에서 지원하는 변수는 두 가지다.
  - `{{today}}`: 오늘 날짜(YYYY-MM-DD)
  - `{{rulesFile}}`: 모드에 따라 CLAUDE.md / AGENTS.md / GEMINI.md
- 자세한 팁은 붙여넣는 글에 넣지 않는다. 편집 창의 가이드 패널에만 보인다.
- 실제 기본 템플릿 15개(5종 × 3모드), 기본 문구, 가이드 항목은 **기본 콘텐츠 문서**에 확정 초안으로 있다. 빌더는 이 텍스트를 그대로 데이터로 옮긴다. 문구를 고치고 싶으면 사용자에게 먼저 묻는다.

## 6. 데이터 **(제안)**
- **저장 위치.** 앱 데이터 폴더의 JSON 파일이다. 사람이 읽을 수 있고, 나중에 모바일 키보드에서 같은 형식을 다시 쓰기 위해서다.
- **데이터 형태 (개념)**
  - 템플릿: id, 이름, 기본 여부, 숨김 여부, 순서, 단축키(없을 수 있음), 모드별 본문 3개
  - 문구: id, 본문, 분류, 추천 모드 목록, 순서
  - 설정: 현재 모드, 검색 팝업 키, 모드 전환 키, 자동 실행, 최근 사용 항목
  - 가이드 항목: 앱에 내장된 읽기 전용 데이터. 사용자 편집 대상이 아니다.
- **기본 템플릿과 사용자 수정의 분리.** 사용자가 기본 템플릿을 고치면 수정본을 따로 저장한다. 앱이 업데이트되어 기본 템플릿이 바뀌어도 사용자 수정본을 덮어쓰지 않는다. "기본값으로 되돌리기"를 누르면 수정본을 지운다.
- **스키마 버전.** 파일에 스키마 버전 번호를 둔다. 나중에 형식이 바뀌면 이 번호로 변환한다.
- 정확한 파일 구성과 필드 이름은 **(빌더 판단)**이다.

## 8. 플랫폼별 메모
- **맥**
  - 손쉬운 사용 권한이 필요하다(4.7).
  - Dock 아이콘 없이 메뉴바 앱으로 동작한다.
  - 개인 사용 단계에서는 서명 없이 빌드해서 쓴다. 배포 단계에서 서명과 공증을 다룬다.
- **윈도우**
  - 트레이 아이콘 메뉴는 메뉴바 메뉴와 같다.
  - 관리자 권한으로 실행된 앱에는 일반 앱이 키 입력을 보낼 수 없다. 이 제한은 문서에 남긴다.
  - **첫 버전 범위 (결정): 윈도우 코드는 함께 쓰되, 실행 검증은 나중에 한다.** 사용자에게는 Apple Silicon 맥만 있고 윈도우 테스트 환경이 없다.
    - 윈도우 전용 코드는 `#[cfg(target_os = "windows")]`로 나눈다. 해당하는 것은 SendInput으로 키 입력 흉내, 포커스 되돌리기, 트레이 메뉴 뒤 직전 창 추적이다.
    - SetForegroundWindow 제한처럼 맥과 동작이 다른 부분은 코드 주석에 남긴다.
    - 가능하면 `cargo check --target x86_64-pc-windows-msvc`로 컴파일만 확인한다. 타깃이나 도구를 설치해야 하면 먼저 사용자에게 묻는다.
    - 완료를 보고할 때 윈도우는 "실행 검증 안 됨"이라고 분명히 적는다. README에도 같은 내용을 남긴다.

## 9. 확인 방법
- **자동 테스트 (TS, vitest 등은 빌더 판단)**
  - 템플릿 렌더링: 자동 변수 치환, 빈칸 유지, 모드별 버전 선택, 빈 버전일 때 대체 동작
  - 채우기 창 로직: 빈칸 찾기, Tab/Shift+Tab 이동 순서, 남은 빈칸 수 계산
  - 검색 필터와 정렬: 추천 문구 우선, 최근 사용 우선
  - 기본/수정본 병합과 되돌리기
  - 단축키 충돌 판정
  - JSON 읽기·쓰기와 스키마 버전 처리
- **Rust**
  - 붙여넣기 흉내와 포커스 복원은 자동 테스트가 어렵다. 아래 수동 점검표로 확인한다.
- **수동 점검표 (맥만, 윈도우는 나중)**
  - 붙여넣기 대상: 터미널의 Claude Code CLI, VS Code 편집기, 크롬의 Gemini 웹 입력창, 메모 앱
  - 채우기 창에서 채운 템플릿을 Claude Code CLI에 붙여넣고 제출했을 때, 접힌 글의 전체 내용이 전달되는지
  - 채우기 창에서 Esc를 누르면 아무것도 붙여넣어지지 않는지
  - 채우기 창에서 ⌘K로 고른 문구가 채우기 창의 커서 위치에 들어가는지
  - 붙여넣기 뒤 원래 클립보드가 복원되는지
  - 수정키를 오래 누르고 있을 때도 올바르게 붙여넣어지는지
  - 검색 팝업에서 넣은 뒤 원래 앱에 붙는지
  - 모드를 바꾸면 같은 단축키가 다른 버전을 붙여넣는지
  - 단축키를 바꾸고 앱을 다시 켜도 유지되는지
  - 권한이 없을 때 대체 동작(클립보드만)이 일어나는지
- 사용자 전역 규칙: 작업 완료 전에 타입 체크, 린트, 관련 테스트를 실행한다. UI는 가능하면 직접 열어 확인한다.

## 10. 열린 질문 (구현을 막지 않음)
- **Gemini를 웹(앱)에서 쓰는지, Antigravity CLI(`agy`)에서 쓰는지.** 첫 버전의 Gemini 템플릿은 양쪽에서 무난하게 쓰이는 형태로 만들었다. 실제로 어디서 쓰는지 알게 되면 템플릿을 조정한다.
- **git 저장소.** 아직 git 저장소가 아니다. 저장소를 만들지, 언제 커밋할지는 사용자가 정한다(사용자 규칙: 커밋은 요청할 때만). 저장소를 만들면 `.superpowers/`(브레인스토밍 임시 파일)를 `.gitignore`에 넣는다.

- 흔한 단축키 경고 목록의 범위
